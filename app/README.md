# نظام الأعمال (Business OS)

نظام تشغيل أعمال معياري (Modular Business OS) — Local-first، عربي RTL أولًا.
هذا المجلد مستقل عن متجر "رفوف" الموجود في جذر المستودع ولا يؤثر عليه.

## المتطلبات

- Node.js 20 أو أحدث
- npm

## التشغيل أثناء التطوير

```bash
npm install
npm run dev
```

يفتح على `http://localhost:5173`.

## البناء للإنتاج

```bash
npm run build   # tsc -b && vite build → يُخرج مجلد dist/
npm run preview # لمعاينة نسخة الإنتاج محليًا
```

## الاختبارات

```bash
npm run test        # يشغّل الاختبارات مرة واحدة (vitest run)
npm run test:watch  # وضع المراقبة أثناء التطوير
```

الاختبارات تغطي: تحقق صحة المدخلات، حساب التقدّم من المهام الفعلية،
الفلاتر والفرز، إحصائيات المشاريع وCRM والمالية (بما فيها تحليل الأشهر
الستة الأخيرة)، منطق التقويم (أحداث يوم معيّن، الأحداث القادمة مرتبة
زمنيًا)، منطق لوحة التحكم ("يحتاج انتباهك" من مهام/صفقات متأخرة فعليًا
وأحداث اليوم)، فهرس البحث الشامل (يستبعد المحذوف، يربط كل نتيجة بأصلها
الحقيقي)، عمليات CRUD الحقيقية عبر IndexedDB لكل وحدة (إنشاء/تعديل/حذف
ناعم واستعادة/حذف نهائي متسلسل/تكرار المشروع مع مهامه، وبالمثل حذف جهة
اتصال نهائيًا يحذف صفقاتها أو حذف ملف)، دورة حياة الصفقة (تغيير المرحلة
يضبط `closed_at` تلقائيًا)، تخزين/استرجاع Blob حقيقي للملفات وتحويله
base64 لأغراض النسخ الاحتياطي (اختبارات هذين الجزءين تُشغَّل صراحةً على
بيئة `node` بدل `jsdom` الافتراضية — انظر التعليق أعلى كل ملف اختبار
لسبب ذلك)، واستمرار البيانات بعد "إعادة تشغيل" قاعدة البيانات (إغلاق
وفتح نسخة جديدة بنفس الاسم).

## قاعدة البيانات

التطبيق **local-first**: كل البيانات تُخزَّن في IndexedDB داخل المتصفح عبر
[Dexie.js](https://dexie.org)، ولا تُرسل إلى أي خادم. القاعدة اسمها
`business_os`، ويمكن فحصها من أدوات المطور في المتصفح
(Application → IndexedDB → business_os).

المخطط معرّف في `src/core/db/schema.ts` بنظام migrations حقيقي (كل
`.version(n)` هو ترحيل إضافي؛ لا يُعدَّل إصدار بعد نشره، بل تُضاف نسخة
جديدة). الجداول الحالية:

- `workspace` — سجل واحد يمثّل مساحة العمل. *(v1)*
- `settings` — إعدادات مفتاح/قيمة (المظهر، تفضيلات العرض). *(v1)*
- `activity_log` — سجل نشاط لكل عملية مهمة (إنشاء/تعديل/حذف/استعادة). *(v1)*
- `projects` — المشاريع. *(v1)*
- `tasks` — المهام (مرتبطة بمشروع، أو مستقلة). *(v1)*
- `contacts` — جهات اتصال CRM (عميل محتمل / عميل). *(v2)*
- `deals` — صفقات CRM (مرتبطة بجهة اتصال، بمراحل: جديدة → تم التواصل →
  عرض مقدَّم → تفاوض → مربوحة/خاسرة). *(v2)*
- `transactions` — حركات مالية (إيراد/مصروف، بفئة وتاريخ، وربط اختياري
  بمشروع أو جهة اتصال). *(v3)*
- `events` — أحداث التقويم (بداية/نهاية، طوال اليوم أو بوقت محدد، وربط
  اختياري بمشروع أو جهة اتصال). *(v3)*
- `files` — ملفات مرفوعة (اسم، نوع MIME، حجم، محتوى Blob فعلي، وربط
  اختياري بمشروع أو جهة اتصال). *(v4)*

## النسخ الاحتياطي

من صفحة **الإعدادات** داخل التطبيق:

- **تصدير نسخة احتياطية**: يُنزّل ملف JSON يحتوي على كل البيانات
  (`{ app, version, exportedAt, workspace, settings, projects, tasks, contacts, deals, transactions, events, files }`).
  محتوى كل ملف مضمَّن كنص base64 (JSON لا يحتمل Blob مباشرة)، لذا قد يكون
  حجم ملف النسخة الاحتياطية أكبر من حجم الملفات الأصلية بنحو الثلث.
- **استيراد نسخة احتياطية**: يتحقق من صحة الملف (اسم التطبيق، رقم الإصدار،
  وجود الحقول المطلوبة)، يعرض ملخصًا بعدد العناصر قبل التنفيذ، يحوّل كل
  ملف من base64 إلى Blob حقيقي، ثم يستورد داخل معاملة واحدة (upsert
  بالمعرّف).

## متغيرات البيئة

لا يحتاج هذا الإصدار (Foundation + Projects) أي متغيرات بيئة أو مفاتيح —
كل شيء محلي. عند إضافة وحدة الذكاء الاصطناعي لاحقًا ستُضاف `.env.example`
توضّح الإعدادات غير السرية فقط (مفاتيح الـ API الفعلية لن تُخزَّن في الكود
أو قاعدة البيانات أو الواجهة الأمامية).

## بنية المجلدات

```
src/
  core/            طبقة الأساس المشتركة بين كل الوحدات
    db/            مخطط Dexie + migrations + bootstrap
    settings/      خدمة الإعدادات + تفضيل المظهر
    activity/      سجل النشاط
    backup/        التصدير/الاستيراد
    ui/            مكوّنات مشتركة (Modal، Toast، Confirm، حالات فارغة/تحميل/خطأ)
    modules.ts     سجلّ الوحدات (ما هو منفَّذ فعليًا مقابل "قريبًا")
  modules/
    dashboard/     لوحة التحكم (تجميع حقيقي من كل الوحدات، لا بيانات وهمية)
    projects/      وحدة المشاريع الكاملة (repository → service → hooks → UI)
    crm/           وحدة العملاء الكاملة (جهات اتصال + صفقات + لوحة Kanban)
    finance/       وحدة المالية (حركات إيراد/مصروف + إحصائيات + تحليل شهري)
    calendar/      وحدة التقويم (أحداث + شبكة شهرية + أجندة + قادمة)
    files/         وحدة الملفات (رفع/تنزيل حقيقي، تخزين Blob محلي)
    search/        البحث الشامل (Ctrl+K، يبني فهرسًا حيًا من كل الوحدات)
    settings/      صفحة الإعدادات
  App.tsx, main.tsx
```

الوحدات غير المنفَّذة (الذكاء الاصطناعي، الوكلاء، سير العمل، الذاكرة،
مكتبة الأوامر، الاستخدام) **لا تظهر كصفحات أو أزرار قابلة للنقر** — فقط
كقائمة نصية غير تفاعلية تحت "قريبًا" في الشريط الجانبي وصفحة الإعدادات،
حتى لا يوحي أي عنصر في الواجهة بأنه يعمل قبل أن يُبنى فعليًا.
